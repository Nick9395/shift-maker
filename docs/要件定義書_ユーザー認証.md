# 要件定義書：ユーザー認証機能

| 項目 | 内容 |
|------|------|
| 対象システム | Shift Maker（シフト管理システム） |
| 版 | 1.1 |
| 作成日 | 2026-07-24 |
| 対象範囲 | サインアップ / ログイン / ログアウト / パスワードリセット |
| 完成イメージ | FigJam 画面遷移図（認証〜メイン画面群） |

---

## 1. 目的

本機能は、シフト管理アプリの利用者を識別・保護し、未ログイン状態では業務画面へアクセスできないようにする。  
認証まわりの画面・遷移は添付の完成図（FigJam）左側のフローに準拠する。

---

## 2. スコープ

### 2.1 対象（In Scope）

| ID | 機能 | 概要 |
|----|------|------|
| AUTH-01 | サインアップ | メール・パスワード（確認付き）でアカウント作成 |
| AUTH-02 | ログイン | メール・パスワードで認証しセッショントークンを発行 |
| AUTH-03 | ログアウト | トークンを失効させ未認証状態に戻す |
| AUTH-04 | パスワードリセット | メールによる再設定手順の送信と新パスワード設定 |
| AUTH-05 | 保護ルート | 未ログイン時はログイン画面へ誘導 |

### 2.2 対象外（Out of Scope / 将来）

- SNS / OAuth ログイン
- 二要素認証（2FA）
- メールアドレス確認（confirmable）の必須化
- 管理者ロール・権限管理
- シフト・カレンダー等の業務画面本体（完成図中央〜右側）。今回は認証後のプレースホルダ画面まで

---

## 3. 想定ユーザー

| 種別 | 説明 |
|------|------|
| 未登録ユーザー | サインアップから利用開始 |
| 登録済みユーザー | ログイン後に業務画面へ進む |
| パスワード失念ユーザー | リセットフローで再設定 |

---

## 4. 画面・遷移要件（完成図準拠）

### 4.1 画面一覧（認証）

| 画面 | パス（フロント） | 主な要素 |
|------|------------------|----------|
| トップ | `/` | アプリ名「Shift Maker」、利用開始 / ログイン / 利用規約 |
| 利用規約（仮） | `/terms` | 仮の利用規約本文、トップへ戻る |
| ログイン | `/login` | Email / Password / ログインボタン / サインアップ・リセットへのリンク |
| サインアップ | `/signup` | Email / Password / Password confirmation / 登録ボタン |
| パスワード再設定依頼 | `/password/forgot` | Email / 送信ボタン |
| 新パスワード設定 | `/password/reset` | Password / Password confirmation（メール内トークン付き） |
| 認証後ホーム（仮） | `/home` | サイドバー付きシェル（完成図のメイン領域のプレースホルダ） |

### 4.2 遷移

```
[未ログイン]
  → /（トップ）
      ├─ 利用開始 → /signup → 成功（自動ログイン）→ /home
      ├─ ログイン → /login → 成功 → /home
      └─ 利用規約 → /terms

  /login
      ├─ サインアップ → /signup
      └─ パスワードを忘れた → /password/forgot → メール送信
            → /password/reset?reset_password_token=... → 成功 → /login

[ログイン済]
  → /home および今後の業務画面
  → ログアウト → /
  → 未認証で保護ページへアクセス → /login
```

### 4.3 UI 方針（完成図）

- 認証画面: 中央カード、濃色ヘッダー、ベージュ系背景
- 認証後: 左サイドバー + メインコンテンツのレイアウト骨格を用意（業務機能は後続）

## 5. 機能要件詳細

### AUTH-01 サインアップ

| 項目 | 内容 |
|------|------|
| 入力 | email（必須・一意）, password（必須）, password_confirmation（必須） |
| バリデーション | Devise 既定（メール形式、パスワード最小長 6 以上） |
| 成功 | ユーザー作成し JWT を `Authorization` ヘッダで返却。フロントはトークンを保存し自動ログイン状態で `/home` へ遷移 |
| 失敗 | 422 とエラーメッセージ |

### AUTH-02 ログイン

| 項目 | 内容 |
|------|------|
| 入力 | email, password |
| 成功 | JWT を `Authorization` ヘッダで返却。フロントはローカルに保存し `/home` へ |
| 失敗 | 401 とエラーメッセージ |

### AUTH-03 ログアウト

| 項目 | 内容 |
|------|------|
| 前提 | 有効な JWT |
| 処理 | JWT を失効リストへ登録し無効化。フロントはトークン削除し `/login` へ |

### AUTH-04 パスワードリセット

| 項目 | 内容 |
|------|------|
| 依頼 | email を受け取り、存在する場合はリセットメール送信（ユーザー列挙を避けるため常に成功メッセージ可） |
| メール | フロントの `/password/reset?reset_password_token=...` へのリンク |
| 再設定 | token + password + password_confirmation で更新。成功後はログイン画面へ |

### AUTH-05 保護ルート

- フロント: 未ログイン時は保護ページを表示せず `/login` へリダイレクト
- API: 要認証エンドポイントは JWT 必須。未認証は 401

---

## 6. 非機能要件

| 項目 | 内容 |
|------|------|
| アーキテクチャ | Backend: Rails API / Frontend: React（Vite） |
| 認証方式 | Devise + devise-jwt（Bearer JWT） |
| CORS | フロント `localhost:3001` を許可。`Authorization` ヘッダを露出 |
| パスワード | bcrypt（Devise database_authenticatable） |
| メール（開発） | ファイル配送（`tmp/mail`）またはログで確認可能にする |
| セキュリティ | パスワードはログに出さない。HTTPS は本番で必須（本ドキュメント時点では開発環境想定） |

---

## 7. API 仕様（概要）

| メソッド | パス | 認証 | 説明 |
|----------|------|------|------|
| POST | `/api/v1/signup` | 不要 | ユーザー登録 |
| POST | `/api/v1/login` | 不要 | ログイン（JWT 発行） |
| DELETE | `/api/v1/logout` | 必要 | ログアウト（JWT 失効） |
| POST | `/api/v1/password` | 不要 | リセットメール送信 |
| PUT | `/api/v1/password` | 不要 | トークンでパスワード更新 |
| GET | `/api/v1/me` | 必要 | ログイン中ユーザー取得 |

### レスポンス例（ユーザー）

```json
{
  "user": {
    "id": 1,
    "email": "user@example.com"
  }
}
```

## 8. データ要件

### users

| カラム | 型 | 説明 |
|--------|-----|------|
| id | bigint | PK |
| email | string | 一意・必須 |
| encrypted_password | string | 必須 |
| reset_password_token | string | リセット用（一意） |
| reset_password_sent_at | datetime | 送信日時 |
| created_at / updated_at | datetime | タイムスタンプ |

### jwt_denylists

| カラム | 型 | 説明 |
|--------|-----|------|
| jti | string | JWT ID（一意） |
| exp | datetime | 有効期限 |

---

## 9. 受け入れ条件（Acceptance Criteria）

1. 未登録メールでサインアップでき、その後ログインできる
2. 誤パスワードではログインできず、エラーが表示される
3. ログイン後にホーム（仮）が表示され、ログアウトできる
4. ログアウト後・未ログイン時に保護ページへ直接アクセスするとログインへ戻る
5. パスワードリセット依頼後、メール（開発環境の配送先）内リンクから新パスワードを設定できる
6. 新パスワードでログインできる
7. 要件・画面遷移が完成図の認証フローと矛盾しない

---

## 10. 今後の拡張（完成図との対応）

完成図中央〜右側の業務画面（一覧・詳細・フォーム・グラフ等）は本要件の後続フェーズとする。  
認証完了後のレイアウト骨格（サイドバー）のみ本実装で用意し、各機能は別要件定義で追加する。
